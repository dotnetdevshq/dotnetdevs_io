# Durable implementation decisions

- PostCSS is updated to 8.5.28, and a scoped npm override makes Next.js use that same version instead of its pinned 8.4.31 dependency. The lockfile also updates Nano ID to 3.3.19. These resolve the remaining production dependency advisories. Reassess the override when upgrading Next.js again; remove it once Next.js supplies a patched PostCSS version itself.

- This replaces the public surface of an existing Next.js 15.3.5 prototype. Next.js and its ESLint configuration were upgraded together to 15.5.25 after Vercel blocked the vulnerable original release. Keep the lockfile committed and apply security updates; React remains on the compatible 18.x line. The previous `src/app`, README, and Next config were preserved under `archive/prototype/`. Old components/data remain unused. They must never be exported as public routes.
- One static page, rendered at build time. Content uses server components; the theme toggle is a small client component. No forms, API integrations, external font requests, or invented audience claims. On September 16, 2026, the owner explicitly requested GA4 (`G-FJLBMHRY60`); it loads after hydration only on the canonical production hostname. The site works without JavaScript, including automatic system dark mode.
- `src/config/site.json` is the content source. All ten URLs were explicitly supplied by the owner on September 15, 2026. The unconfirmed URLs from the old prototype were not reused.
- External links open in the same tab. Entire cards are anchors with visible text and decorative icons. No nested buttons. A `#main` skip link is an intentional in-page navigation target, not a placeholder destination.
- Unconfigured/disabled social links are omitted in production. `npm run dev:preview` allows non-interactive samples only when both NODE_ENV is development and SOCIAL_PREVIEW is 1. A production build cannot enable these samples.
- The owner requested glassmorphism and removal of the redundant header wordmark after supplying the logo. Both themes use translucent surfaces, blur, edge highlights, and static ambient gradients, with solid-surface fallbacks. The header shows only the original rounded logo; the hero says “Your .NET community.” Newsletter artwork is a decorative typographic cover, not a fake newsletter issue.
- The production homepage canonical is `https://dotnetdevs.io/`. Staging noindex can be set at build time. No social handles are added to metadata.
- Vercel is the owner's deployment target. Live checks of the canonical homepage, robots.txt, and sitemap.xml returned 200 on September 16, 2026. Local changes still require deployment. Cloudflare Pages and GitHub Pages remain alternatives. No contact destination was supplied.
- Dark mode was explicitly requested after the first version. CSS follows system preference by default. The header toggle stores a light/dark override under `dotnetdevs-theme`; a small inline head script applies it before paint. Storage failures are tolerated. With JavaScript disabled the toggle is hidden, and CSS continues following the system. No theme library or dependency was added.
- The owner supplied `C:\Users\Levan Jintcharadze\Downloads\NET devs - logo\1.png` as the brand logo and explicitly requested the original square with rounded corners. `public/logo.png` retains the full 500 × 500 source; the header scales it proportionately with CSS rounding, and the sharing image also uses the full square. The previous crop is unused. Logo/icon paths are configured in `src/config/site.json`.

- Phase 1 content hub (October 16, 2026): the site grows from one link page into a small hub with `/newsletter/`, `/links/`, `/links/<topic>/` and `/sponsor/`. Content stays in versioned JSON under `src/content/`; there is still no backend, CMS or client-side fetching. Issues are not republished on dotnetdevs.io: the archive links to dotnet.news, which remains the canonical home of each issue. The link library was seeded from Issues 28 to 30 as published on Beehiiv, excluding Beehiiv ad placements. Authors are recorded only where the issue named them (Issue 30), plus Damien Bowden as the author of his own blog; other entries keep `author: null`. Sponsor figures come from the owner's October 8, 2026 audience snapshot and are shown with their dates. The contact destination is `mailto:info@dotnetdevs.io`, which the owner uses for dotnetdevs.io communication. The header note "A shared love of .NET." was replaced by the main navigation.

- Phase 2 (October 16, 2026): the link library was backfilled from Issues 1 to 27 as published on Beehiiv (ad placements excluded), giving 338 unique links; a URL featured in several issues is kept once under its first issue. Topics were assigned by keyword rules and then reviewed by hand; `observability` and `clients` (MAUI and desktop) were added. Authors are filled in only from the issue itself or for single-author personal blogs where the blog owner is the author; all other entries keep `author: null`. Added `/guides/` with a first reading path (AI agents and MCP in .NET) whose sections reference library URLs only, and `/posts/` for social cards, starting with the memory-dump card based on Aaron Powell's .NET Blog article (read before summarizing). Guides and Posts are linked from the footer, homepage and library rather than the header, to keep the phone header to three items.

- Redesign (October 21, 2026): the owner reviewed two mockup directions and chose A ("refined": the existing warm neutral and violet look with a new structure). Header navigation is now Newsletter, Library, Guides, Posts plus a Subscribe button; Sponsor moved to the footer. The homepage leads with the purpose and a subscribe call to action, then the latest issue, topics, the guide and the newest post, with social channels reduced to one row. The glass and backdrop-blur treatment was removed in favor of plain cards. The library gained client-side search, a topic sidebar, and collapsed older issues. Subscribe buttons go to Beehiiv's hosted page (`newsletter.subscribeUrl`); an inline email field would need a Beehiiv embed form, which the publication does not have yet. The header logo, favicon and sharing image use the owner's new `<·>` mark. The LinkedIn figure on the homepage is the dated October 2026 snapshot from `media-kit.json`, rounded down.
